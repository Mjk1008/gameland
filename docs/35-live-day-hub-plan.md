# ۳۵ — جایگزینِ تبِ «دعوت»: هابِ زنده‌ی روزِ مسابقه

**Stage:** Plan (برای اجرا تو سشنِ بعدی) · **Status:** 📝 نوشته‌شده، اجرا نشده · **جایگزینِ:** `docs/NOW.md`'s «مچ‌سنتر» (کدِ Cursor رد شد، از صفر طراحی شد)

> این سند خروجیِ یه گفتگوی طراحیه، نه کدنویسی. هدف: یه پلنِ کامل و قابلِ‌اجرا که سشنِ بعدی مستقیم شروع کنه به ساختن، بدون اینکه دوباره طراحی کنه.

---

## ۰. چرا الان، و چرا از صفر

همین امروز قرعه‌کشیِ استان‌ها شروع شده، براکت‌ها دارن جمع می‌شن سمتِ فینال. تبِ «دعوت» (کمپینِ رفرال) پایینِ صفحه، این روزها **کمترین ارزش** رو داره — چیزی که بازیکن‌ها الان واقعاً می‌خوان اینه: *«من کجام؟ با کی بازی دارم؟ الان کجا وایسم؟ اطراف چه خبره؟»*

کدِ WIP‌ای که Cursor رو مکِ کاربر ساخته بود (`web/app/center`, `lib/match-center*`) دو مشکلِ بنیادی داشت:
1. **اصلاً اجرا نمی‌شد** — به یه زیرساخت (`MatchDesk` تو `store.ts`) وابسته بود که همون روز که ساخته شد، یه کامیتِ دیگه برش گردوند چون جلوی بیلدِ پروداکشن رو گرفته بود.
2. **طراحیِ اطلاعاتی ضعیف** — یه لیستِ جدولیِ خشک از وضعیت‌ها، نه چیزی که حسِ «الان وسطِ یه رویدادِ زنده‌ام» بده.

این سند از صفر طراحی می‌کنه، نه پچ‌کردنِ اون کد. اسمِ پیشنهادی: **«امروز»** (مسیر: `/today` یا `/center` — هرکدوم، جزئیاتِ کوچیکه) — چون دقیقاً همون سوالی رو جواب می‌ده که بازیکن تو ذهنشه.

## ۱. کارهایی که این فیچر باید انجام بده (Jobs-to-be-done)

### برای بازیکن
1. **«الان چه وضعیتمه؟»** — بدونِ اسکرول، همون لحظه‌ی اول جواب بگیره: منتظرم / آماده‌ام / دارم بازی می‌کنم / بردم / باختم / صعود کردم.
2. **«با کی، کجا، کِی؟»** — حریفِ بعدی، محل، دستگاه/ایستگاه، بازه‌ی زمانی.
3. **«الان دورم چه خبره؟»** — یه فیدِ زنده از کلِ رویداد: کی داره بازی می‌کنه، نتایجِ تازه، بدونِ اینکه خودش بره تو هر براکت بگرده.
4. **«نکنه بازیم رو از دست بدم؟»** — نوتیفِ فعال: «حریفت حاضر شد»، «نوبتته»، «برو ایستگاهِ N».
5. **«دوستامو دنبال کنم.»** — فالوِ بازیکنای دیگه، دیدنِ وضعیتشون بدون رفتن تو براکتِ اونا.
6. **«قوانینِ بازیم چیه؟»** — دسترسیِ سریع به قوانینِ همون رشته (این بخش از قبل ساخته شده: `rulesForDisc`).

### برای ادمین
1. **«کدوم بازی گیر کرده؟»** — صفِ منتظر / درحالِ‌بازی / دیرکرده / غایب / درخواستِ‌داور، یه‌جا.
2. **«کدوم دستگاه/میز آزاده؟»** — تختهٔ ایستگاه‌ها: الان کی، بعدی کی.
3. **«باید کیو صدا کنم؟»** — یه دکمه که هم پیامِ آماده می‌سازه (`callCopy` از قبل هست) هم نوتیف می‌فرسته.
4. **«یه اعلانِ عمومی/گروهی بدم.»** — از مکانیزمِ موجودِ `match-announce` استفاده کنه، گسترش‌یافته به سطحِ رویداد/استان نه فقط یه بازی.
5. **«نبضِ کلیِ روز چیه؟»** — استان‌به‌استان، چند درصد تموم شده.

## ۲. معماریِ اطلاعات (چیدمانِ صفحه)

### صفحه‌ی اصلیِ بازیکن (`/today`)

```
┌─────────────────────────────┐
│  کارتِ هیرو — وضعیتِ من      │  ← بزرگ، رنگی، همون اول دیده می‌شه
│  (منتظر/آماده/بازی/نتیجه)    │     رنگ بر اساسِ وضعیت عوض می‌شه
├─────────────────────────────┤
│  فیدِ زنده (لایو تیکر)        │  ← اسکرولِ عمودی، شبیهِ فیدِ ورزشیِ زنده
│  «X بردِ Y رو Z»              │     آواتار، تگ، زمانِ «همین الان»
│  «A داره با B بازی می‌کنه»    │
├─────────────────────────────┤
│  نبضِ استان‌ها (نواری/درصدی)  │  ← جایگزینِ لیستِ خشکِ Cursor
├─────────────────────────────┤
│  کسایی که فالو می‌کنی         │
└─────────────────────────────┘
```

- **کارتِ هیرو** تنها جایی‌ه که کاربر مجبور نیست چیزی رو تشخیص بده — فقط رنگ و متن. اگه بازیِ فعال داره، دکمه‌های «حاضرم» / «آماده‌ام» / «درخواستِ داور» همینجاست.
- **فیدِ زنده** با انیمیشنِ ورودِ آیتمِ جدید (ظریف، نه مزاحم) — حسِ زنده‌بودن می‌ده. باید با `IntersectionObserver`/polling ساده باشه، نه websocket (هم‌خوان با معماریِ فعلیِ اپ).
- **نبضِ استان‌ها**: هر استان یه نوارِ پیشرفت (`X از Y تموم`)، نه فقط عدد. کلیک → می‌ره تو جدولِ همون استان (بریج به `BracketView` موجود).

### صفحه‌ی ادمین (بخشِ جدید تو `/admin`، نه یه اپِ جدا)

```
┌─────────────────────────────┐
│  تختهٔ ایستگاه‌ها (Station Board)│  ← هرکارتِ ایستگاه: الان/بعدی/وضعیت
├─────────────────────────────┤
│  تب‌ها: منتظر | درحالِ‌بازی |   │
│         دیرکرده | غایب | داور │
├─────────────────────────────┤
│  دکمه‌ی «صدا کن» رو هر ردیف   │  ← callCopy + پوش‌نوتیف با یه تپ
├─────────────────────────────┤
│  اعلانِ گروهی (استان/رشته/همه) │
└─────────────────────────────┘
```

مهم: این **کنارِ** `run-panel.tsx` فعلی میاد، جایگزینش نمی‌کنه — چون همین الان داره برای ثبتِ نتیجه استفاده می‌شه و روزِ مسابقه نباید قطع بشه. تختهٔ ایستگاه‌ها فقط *پیدا‌کردنِ* بازیِ درست رو راحت می‌کنه؛ ثبتِ نتیجه همون مسیرِ فعلی (`run-panel`/`MatchOps`) رو استفاده می‌کنه که همین الان کار می‌کنه و تازه امن‌ترش کردیم (confirm dialogها).

## ۳. زیرساختِ بک‌اند — این‌بار درست

### چرا بارِ قبل شکست
کامیتِ `dfd648e` یه `MatchDesk` به `store.ts` اضافه کرد ولی **loaderِ hydration‌ش رو تو `persistence.ts` کامل نکرد** — همون روز تایپ‌چکِ Next رو رد کرد و دیپلوی رو بلاک کرد، پس `764e00c` کاملاً برش گردوند.

### قانون این‌بار
هر جدول/فیلدِ جدید باید **همون کامیت** این سه‌تا رو با هم داشته باشه، نه جدا:
1. تعریفِ تایپ/schema (`lib/db/schema.ts`)
2. مایگریشنِ self-healing (`CREATE TABLE IF NOT EXISTS` / `ALTER TABLE ADD COLUMN IF NOT EXISTS` تو `persistence.ts`)
3. لودرِ hydration تو `startHydration()` تو `store.ts`

و قبلِ commit، `npm run build` واقعی (نه فقط dev) لوکال یا رو یه سشنِ با node_modules زده بشه — همینی که تو این سشن نتونستیم چک کنیم چون sandbox نتِ محدود داشت.

### جدول‌های/فیلدهای جدید

| چی | کجا | برای چی |
|---|---|---|
| `app_match_desk` (matchId PK, p1Here, p1Ready, p2Here, p2Ready, station, calledAt, refBy, refAt) | جدولِ جدید | چک‌این و وضعیتِ عملیاتیِ هر بازی |
| `app_follows` (followerId, followeeId) | جدولِ جدید | گراف فالو |
| `app_settings` کلیدِ `TODAY_HUB_ENABLED` | همون جدولِ settings موجود | on/off دستیِ ادمین (مثلِ الگوی Arena) |

### گیت‌کردنِ فیچر
دقیقاً الگویِ `isArenaEnabled()`/`isMatchCenterEnabled()` موجود رو کپی کن: env var می‌تونه force-on کنه، admin setting می‌تونه force-off کنه، پیش‌فرض: خودکار روشن وقتی حداقل یه رویداد `status === 'live'` باشه.

### API
- `GET /api/today` → snapshot (بازسازیِ `buildCenterSnapshot` ولی بهینه‌تر — نتیجه رو برای چند ثانیه cache کن چون هر پول یه بازسازیِ کاملِ آرایه‌ست، رو مقیاسِ فعلی (~هزاران کاربر) مشکلی نیست ولی مفته که caching باشه).
- `POST /api/today/action` → همون عملیاتِ `here`/`ready`/`ref`/`follow`/`unfollow`.
- `POST /api/admin/today/call` → صدا کردنِ یه بازی به یه ایستگاه (نوتیف + `callCopy`).
- polling: هر ۸-۱۰ ثانیه برای صفحه‌ی زنده (نه ۳۰ ثانیه‌ی معمولِ نوتیف‌کانت — این صفحه قراره حسِ زنده بده)، ولی با یه بک‌آفِ ساده اگه تب پس‌زمینه‌ست (`document.visibilityState`).

## ۴. نکاتِ اجباری از تجربه‌ی قبلیِ اپ (CLAUDE.md)

- هر مودال/فیدِ شناور → `createPortal` به `document.body` (نه inline)، وگرنه تو صفحه‌ی انیمیشن‌دارِ خونه گیر می‌کنه.
- هیچ عکس/آواتاری inline base64 نشه — از الگویِ blob-API موجود (`/api/avatar/[id]`) استفاده کن.
- اگه فیدِ زنده افقی اسکرول شد، `direction: 'ltr'` رو خودِ container بذار (RTL باگِ شناخته‌شده).
- شماره‌تلفن هیچ‌جا به غیرِ ادمین نشون داده نشه — اطلاعاتِ «غایب» فقط تگ/نام، نه تماس مستقیم (اگه تماس لازمه، از مسیرِ ادمین‌گیت‌شده‌ی فعلی).
- کپی‌رایتینگ: هیچ متنِ توضیحی/راهنمای اضافه ننویس — فقط برچسبِ کوتاه، مثلِ بقیه‌ی اپ.
