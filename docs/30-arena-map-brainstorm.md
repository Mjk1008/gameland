## مشکل واقعی (نه visual)

کاربر باید بفهمه:
1. **کجا** درخواست بازی باز هست؟
2. **چند تا** — و آیا نزدیک شهر خودشه؟
3. **سریع** بره سمت قبول یا ساخت درخواست.

نقشه لازم نیست — فقط اگه **کشف سراسری** رو سریع‌تر از dropdown استان/شهر کنه.

---

## گزینه A — «شهر-چیپ» (پیشنهاد MVP)

بدون نقشه. ردیف افقی از chip شهرهای فعال:

```
[ تهران 4 ] [ مشهد 2 ] [ شیراز 1 ] [ اصفهان 3 ] …
```

- مرتب بر اساس فاصله از شهر پروفایل یا تعداد درخواست
- تپ = فیلتر لیست
- **Pros:** ساده، موبایل‌فرند، همون dark + بنفش اپ
- **Cons:** حس «سراسری» کمتر از نقشه

**Effort:** ~نیم روز

---

## گزینه B — «heatmap استان» (static SVG)

SVG ساده ایران — ۳۱ استان، رنگ بر اساس تعداد درخواست باز:

| سطح | رنگ |
|-----|-----|
| 0 | `#262019` (sf2) |
| 1–2 | `#581c87` |
| 3–5 | `#9333ea` |
| 6+ | `#a855f7` + glow |

- کلیک استان → فیلتر + لیست شهرها
- بدون pan/zoom، بدون canvas
- **Pros:** Dribbble-friendly، سبک، قابل export
- **Cons:** جزئیات شهر نداره

**Effort:** ۱–۲ روز (SVG + interaction)

---

## گزینه C — «کارت شهر» (grid)

Grid 2 ستونه کارت شهرهایی که درخواست دارن:

```
┌─────────────┐  ┌─────────────┐
│  تهران      │  │  مشهد       │
│  ●●●● 4     │  │  ●● 2       │
│  FC · PES   │  │  FC         │
└─────────────┘  └─────────────┘
```

- **Pros:** خیلی readable، بدون abstraction نقشه
- **Cons:** ۳۰+ شهر شلوغ می‌شه → scroll + sort

**Effort:** ~۱ روز
