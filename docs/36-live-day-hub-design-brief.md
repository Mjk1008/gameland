# بریفِ طراحی — «امروز» (هابِ زنده‌ی روزِ مسابقه)

> این سند برایِ دادن به یه ابزارِ طراحی (Claude Design) آماده شده. پسِ‌زمینه‌ی فنی/تصمیم‌های مهندسی تو `docs/35-live-day-hub-plan.md` هست؛ اینجا فقط چیزی که برای طراحیِ UI لازمه.

## یک‌خطی
یه صفحه (جایگزینِ تبِ «دعوت» پایینِ اپ) که روزهای مسابقه، بازیکن همون لحظه‌ی اول بفهمه «کجام، با کی بازی دارم، الان دورم چه خبره» — و ادمین یه تخته‌ی عملیاتی برای اداره‌کردنِ روز داشته باشه.

## زمینه‌ی محصول
- اپِ گیم‌لند: پلتفرمِ تورنومنتِ ایسپورتس، **فارسی، RTL، موبایل‌فرست، تمِ تیره**.
- کاربر یه بازیکنه که تو یه تورنومنتِ چندمرحله‌ای (مقدماتیِ استانی → فینال) ثبت‌نام کرده و همین روزها داره بازی می‌کنه.
- ادمین یه برگزارکننده‌ست که وسطِ اجرای روزِ مسابقه‌ست — استرس و شلوغیِ واقعی داره، باید سریع تصمیم بگیره.

## چیزی که **نباید** طراحی بشه (خارج از اسکوپ)
چت، ویدیو/استریم، هرگونه UI برایِ تغییرِ منطقِ قرعه/براکت. این صفحه فقط نمایش + چک‌این‌ه.

## صفحه‌ی ۱ — خانه‌ی «امروز» (بازیکن)

هدف: بدونِ اسکرول، وضعیتِ کاربر مشخص باشه.

### بخش‌ها (از بالا به پایین)
1. **کارتِ هیرو — وضعیتِ من.** بزرگ‌ترین المانِ صفحه. رنگ بر اساسِ وضعیت عوض می‌شه:
   - `منتظرم` (خاکستری/tmut) — هنوز نوبتم نرسیده
   - `آماده‌ام` (طلایی) — نوبتم نزدیکه یا حریف حاضر شده
   - `دارم بازی می‌کنم` (قرمزِ زنده، شاید یه پالسِ ملایم) — بازی در جریانه
   - `بردم` (طلایی، حسِ جشن) / `باختم` (خنثی) / `صعود کردم` (طلایی، برجسته‌تر)
   محتوا: نامِ حریف + تگ + آواتار، رشته، دور (مثلاً «یک‌چهارم نهایی»)، محل/ایستگاه/بازه‌ی زمانی اگه مشخص باشه. اگه بازیِ فعال داره: دکمه‌های «حاضرم» / «آماده‌ام» / «درخواستِ داور» همینجا.
2. **فیدِ زنده (تیکر).** لیستِ عمودیِ رویدادهای تازه‌ی کل رویداد: «X بردِ Y رو Z» با آواتار و «همین الان»/«۲ دقیقه پیش». حسِ یه فیدِ ورزشیِ زنده، نه یه جدول. ورودِ آیتمِ جدید می‌تونه یه فِیدِ ظریف داشته باشه.
3. **نبضِ استان‌ها.** به‌جای لیست، هر استان یه نوارِ پیشرفتِ کوتاه (مثلاً «تهران — ۱۴ از ۲۰ تموم»)، افقی، قابلِ اسکرول یا گرید.
4. **کسایی که فالو می‌کنی.** ردیفِ کوچیکِ آواتار+نام+وضعیتِ فعلی، تپ → می‌ره تو جزئیاتِ بازیِ اون بازیکن.

### حالت‌های لازم برای طراحی
- بازیکن الان بازیِ فعال نداره ولی رویداد در جریانه (فقط فیدِ زنده رو ببینه، کارتِ هیرو یه پیامِ خنثی).
- بازیکن حذف شده (کارتِ هیرو حالتِ «باختم»، ولی هنوز فیدِ زنده و فالوها فعاله).
- هیچ رویدادِ زنده‌ای نیست (این تب اصلاً نباید نشون داده بشه؛ طراحیِ empty-state لازم نیست).

## صفحه‌ی ۲ — جزئیاتِ بازی (شیت/مودال، از رویِ کارتِ هیرو یا فیدِ زنده باز می‌شه)

- دو بازیکن رو‌به‌رو (مثلِ صفحه‌ی براکتِ فعلی: نام، تگ، آواتار، رتبه اگه داشته باشن).
- محل، آدرس، نقشه (اگه هست)، بازه‌ی زمانی، شماره‌ی ایستگاه/دستگاه.
- دکمه‌های چک‌این («حاضرم»، «آماده‌ام» — دوتا پله‌ی جدا، نه یه دکمه) + «درخواستِ داور».
- لینکِ کوتاه به قوانینِ همون رشته (متنِ آماده از قبل هست، فقط نمایشش لازمه — یه شیتِ کوچیکِ جدا یا آکاردئون).

## صفحه‌ی ۳ — تخته‌ی عملیاتیِ ادمین

هدف: کسی که وسطِ شلوغیِ روزِ مسابقه‌ست، ظرفِ ۲ ثانیه بفهمه چیکار کنه.

### بخش‌ها
1. **تختهٔ ایستگاه‌ها.** گریدِ کارت، هر کارت = یه ایستگاه/دستگاه: شماره، بازیِ الان (دو اسم)، بازیِ بعدی، وضعیت (رنگی: آزاد / درحالِ‌اجرا / دیرکرده).
2. **تب‌های صف:** منتظر · درحالِ‌بازی · دیرکرده (قرمز، برجسته) · غایب (قرمز، برجسته‌تر) · درخواستِ‌داور. هر ردیف: دو اسمِ بازیکن، شماره‌ی بازی، از کِی تو صفن (تایمرِ نسبی: «۱۲ دقیقه»)، دکمه‌ی «صدا کن».
3. **اعلانِ گروهی.** فرمِ کوچیک: انتخابِ گروه (همه/یه استان/یه رشته) + متن (یا یکی از قالب‌های آماده) + دکمه‌ی ارسال.

### نکته‌ی طراحی
این صفحه باید **متراکم و اسکن‌پذیر** باشه — ادمین وایساده وسطِ سالن داره چک می‌کنه، نه راحت نشسته پای لپ‌تاپ. تایپوگرافیِ فشرده‌تر از صفحه‌ی بازیکن قابلِ قبوله.

## خروجیِ موردِ انتظار
موکاپِ موبایل (عرضِ ~۳۷۵-۴۲۸px)، تمِ تیره، برایِ هر سه صفحه + حالت‌های ذکرشده. اگه ابزار پروتوتایپِ کلیک‌پذیر هم می‌سازه عالیه، ولی استاتیک هم کافیه — قراره من (کلود) از رویِ همین کدشو بزنم.
